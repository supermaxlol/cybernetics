# cybernetics — machine-checked results on organs of a viable agent

A Lean 4 + Mathlib library of theorems about what a goal-directed agent needs to stay viable:
memory, a checker ("Watcher"), a brake (feedback with delay), a skin (bounded exposure), a
spotlight (limited attention), and how these combine. A second half asks when a coarse,
macro-level model can stand in for a fine, micro-level one (the cross-scale map φ), and gives
statistical tests of that, with their error rates proved.

**527 audited theorems, 0 `sorry`, axioms used: only `propext`, `Classical.choice`, `Quot.sound`**
(see `AXIOM_AUDIT.txt`, produced by `#print axioms` on every theorem listed in
`FiveOrgans/Audit.lean`).

## What the proofs show, and what they do not

Every theorem is a statement about a **mathematical model** under stated hypotheses. A
machine-checked proof means the conclusion follows from the hypotheses; it does **not** mean any
real system (an organism, a firm, an AI agent, a market) satisfies those hypotheses. Whether one
does is an empirical question the library does not settle. In particular:

* the organ theorems hold for the stylised dynamics in each file (linear brakes, binary Watcher
  decisions, finite Markov chains, hazard sequences, ...);
* `OpenWorld.lean` proves that "exactly five organs" is **not** a theorem: no finite organ list is
  complete for an open class of worlds; `OrganCount.lean` gives the relative statement for a
  closed one;
* the statistical modules (`RowConcentration`, `CrossScaleContrast`, `DiffContrast`,
  `RandomCount`, and the variance-adaptive `PoissonTail` … `BennettDiff`) prove error rates
  **given** a sampling model (data generated by a
  time-homogeneous Markov chain at the order used). `MarkovOrder`, `MarkovOrderK` and
  `FadingMemory` cover what happens when that order is wrong or the memory only fades.

`FiveOrganAgent` and `CanonicalAgent` are different capstones. The first combines five
*failure channels*, where memory appears twice (two-speed and history) and the Watcher does
not appear. The second combines the conceptual five organs: the two memory demands are merged
into one organ (a relabelling; survival is unchanged), and the Watcher gets its own demand.

Docstrings occasionally cite experiment notes (e.g. "S126", `notes/`, `analysis/`). Those refer to
a private working folder that is not part of this repository; they are motivation only, and no
theorem depends on them.

## Choosing a difference test

The four two-sample rules for a [0,1] outcome make different trade-offs. All four have a proved
false-rejection bound under independent draws with a common mean.

| Rule | Theorem | Best when |
|---|---|---|
| Hoeffding on p̂₁ − p̂₂ | `DiffContrast.diff_tail` | p near 1/2; any dependence between the two samples allowed |
| KL interval overlap | `BernKL.kl_two_sample_bern` | rare outcomes; any dependence between the two samples allowed |
| Direct Bernoulli-mgf difference | `BennettDiff.bern_diff_two_sample` | most cases (variance q(1−q)); needs all draws jointly independent |
| Random counts | `BennettRandom.bern_diff_random_alpha`, `BernKL.kl_two_sample_bern_random_alpha`, `RandomCount.random_diff_alpha` | visit counts not fixed in advance; all pay a union bound over counts and are conservative |

A simulation on known Markov chains (private working folder, exploratory, not part of this
repository) found the direct Bernoulli-mgf test the most powerful of these in every scenario tried.
That result is about the simulated chains, not about any real system.

## Build

Requires [elan](https://github.com/leanprover/elan). The toolchain (Lean 4.35.0) and Mathlib
(`v4.35.0`) are pinned in `lean-toolchain` and `lakefile.toml`.

```
lake exe cache get      # prebuilt Mathlib
lake build              # builds every module (FiveOrgans.lean imports them all)
scripts/audit.sh        # rebuilds and regenerates AXIOM_AUDIT.txt
```

The audit in this repository was produced by compiling each file with Lean 4.35.0 against
Mathlib v4.35.0.
